Kiến trúc Tổng quan 3 Tầng Khép kín (Closed-Loop IoT & Java Web MVC)

Hệ thống tưới cây thông minh hoạt động theo vòng lặp khép kín 2 chiều không chặn (Non-blocking Closed-Loop): Mạch ESP8266 vừa đẩy dữ liệu 4 cảm biến lên Server mỗi 5 giây, vừa lắng nghe lệnh Bật/Tắt máy bơm từ giao diện Web mỗi 1 giây.

TẦNG 1: THIẾT BỊ NHÚNG IOT (ESP8266 NodeMCU • Smart_Irrigation_Projec_IoT.cpp)
Non-Blocking millis()
Cảm biến Độ ẩm đất (A0) Đọc ADC 1023..400 → Quy đổi 0%..100%.
Ánh sáng LM393 (D1/GPIO5) Digital: 0 = Trời Sáng, 1 = Trời Tối.
Nhiệt/Ẩm DHT11 (D2/GPIO4) Đo nhiệt độ (°C) & độ ẩm không khí (%).
Cân HX711 (D5/D6) & Relay (D7) Cân khối lượng chậu (gram) & Đóng/Ngắt máy bơm.
Chiều lên (Mỗi 5s): POST /api/sensor/readings (JSON 4 cảm biến)
Chiều xuống (Mỗi 1s): GET /api/watering/command?potId=1 (Lệnh START / STOP)
TẦNG 2: BACKEND JAVA WEB MVC (Apache Tomcat 9 • Servlet / Service / DAO / SQL Server)
Port 8080
AuthFilter.java Whitelist cho /api/* (IoT M2M), kiểm tra Session cho các trang Web.
SensorApiServlet.java Nhận JSON từ ESP8266, lưu SQL Server (SensorDataDAO) & cập nhật Cache.
WateringCommandServlet.java Quản lý hàng đợi lệnh COMMAND_QUEUE & trạng thái PUMP_ACTIVE.
AppDataService.java Đánh giá sức khỏe cây, sinh cảnh báo & tính hiệu chuẩn lưu lượng bơm (ml/s).
AJAX Polling (Mỗi 3–5s): Tự động cập nhật số liệu cảm biến & nút máy bơm không cần F5
Tương tác Người dùng: Bấm Bật bơm hẹn giờ / Tắt bơm khẩn cấp / Xác nhận cảnh báo
TẦNG 3: GIAO DIỆN NGƯỜI DÙNG THỜI GIAN THỰC (JSP Views + Fetch AJAX JavaScript)
Realtime UI
Dashboard (/dashboard) Tổng quan KPI, danh sách chậu cây & điều khiển tưới nhanh.
Cảm biến (/sensors) Hiển thị trực tiếp 4 cảm biến từ ESP8266 & biểu đồ xu hướng 24h.
Điều khiển tưới (/watering-management) Bật bơm hẹn giờ (5..120s), Tắt khẩn cấp & Lịch sử tưới.
Cảnh báo & Phân tích (/alerts, /analytics) Quản lý cảnh báo DRY_STRESS / SENSOR_FAULT & lưu lượng bơm.

Luồng 1: Đăng nhập Người dùng & Cơ chế Whitelist cho Thiết bị IoT

Mọi HTTP Request gửi tới Server đều đi qua chốt chặn đầu tiên là AuthFilter.java. Bộ lọc này phân biệt rõ người dùng trình duyệt (cần đăng nhập Session) và vi điều khiển ESP8266 (giao tiếp qua API Whitelist).

Bước 01

Gửi Request tới Server

Trình duyệt hoặc mạch ESP8266 gửi yêu cầu HTTP tới cổng 8080 của Tomcat.

Bước 02

AuthFilter Kiểm tra Đường dẫn

Kiểm tra URI có nằm trong danh sách công khai (/login, /css/*, /js/*, /api/*) hay không.

Bước 03 (Nhánh Web)

Kiểm tra Session user

Nếu truy cập /dashboard mà chưa có Session, tự động chuyển hướng (Redirect) về trang /login.

Bước 04 (Nhánh IoT)

Cho phép M2M /api/*

Các đường dẫn /api/sensor/readings và /api/watering/command được đi thẳng vào Servlet xử lý.

Tại sao phải mở Whitelist cho /api/sensor/readings và /api/watering/command? Vi điều khiển ESP8266 dùng thư viện ESP8266HTTPClient không lưu trữ JSESSIONID Cookie như trình duyệt. Nếu không khai báo Whitelist trong AuthFilter.java, Server sẽ trả về mã 302 Redirect về trang đăng nhập khiến ESP8266 không thể gửi dữ liệu cảm biến hay nhận lệnh bật bơm.

Luồng 2: Thu thập & Đồng bộ 4 Cảm biến Thời gian thực (Mỗi 5 Giây)

Chu trình khép kín đưa thông số vật lý từ chậu cây thật ngoài đời lên cơ sở dữ liệu SQL Server và hiển thị tức thời trên màn hình người dùng mà không cần tải lại trang.

1

ESP8266 đọc 4 cảm biến mỗi 5000ms (Smart_Irrigation_Projec_IoT.cpp)

Khi currentMillis - previousMillis >= 5000, vi điều khiển đọc đồng thời: Độ ẩm đất (A0), Ánh sáng LM393 (D1), Nhiệt độ & Độ ẩm không khí DHT11 (D2), và Khối lượng chậu cây từ cân Loadcell HX711 (D5/D6).

2

ESP8266 đóng gói JSON gửi POST /api/sensor/readings

Hàm sendDataToWebApp(moisture, light, t, h, weight) dùng thư viện ArduinoJson tạo chuỗi JSON và gửi HTTP POST lên địa chỉ IP của máy chủ Java Web.

3

SensorApiServlet.doPost() bóc tách JSON & Lưu trữ

• Gọi SensorDataDAO.insertReading(potId, moisture, light) để ghi bản ghi lịch sử vào bảng SensorReadings trong SQL Server.
• Lưu đồng thời Nhiệt độ (temp), Độ ẩm không khí (hum) và Cân nặng (weight) vào bộ nhớ đệm thời gian thực (LATEST_TELEMETRY).
• Gọi AppDataService.recordLiveTelemetry(...) để cập nhật trạng thái chậu cây và kiểm tra ngưỡng cảnh báo.

4

Giao diện Web tự động kéo dữ liệu mới (AJAX Polling)

Các trang dashboard.jsp (qua dashboard.js) và sensors.jsp (qua sensors.js) chạy bộ đếm setInterval mỗi 4–5 giây gọi GET /api/sensor/readings?potId=1 để cập nhật trực tiếp các con số trên giao diện.

Cấu trúc JSON trao đổi tại /api/sensor/readings

// 1. Gói tin ESP8266 gửi lên (POST /api/sensor/readings):
{
  "potId": 1,
  "moisture": 58,
  "light": 0,
  "temp": 29.2,
  "hum": 73.5,
  "weight": 385.0
}

// 2. Gói tin Server trả về cho Giao diện Web (GET /api/sensor/readings?potId=1):
{
  "status": "success",
  "potId": 1,
  "soilMoisture": 58.0,
  "lightStatus": "SUNNY",
  "temperature": 29.2,
  "airHumidity": 73.5,
  "weightGrams": 385.0,
  "pumpActive": false
}
Luồng 03 • Chiều từ Giao diện Web xuống Thiết bị IoT & Báo ngược về Web

Luồng 3: Điều khiển Bật Máy Bơm Hẹn Giờ & Tự Động Tắt Khép Kín

Giải quyết bài toán đồng bộ trạng thái giữa phần mềm và phần cứng: Người dùng bấm nút trên Web → ESP8266 bật bơm đúng số giây yêu cầu → Tự ngắt Relay → Báo ngược về Web để nút bấm tự trở lại trạng thái nghỉ.

1

Người dùng chọn thời lượng tưới và bấm "Bật Bơm Ngay" trên Web

Tại trang wateringManagement.jsp (hoặc dashboard.jsp), người dùng kéo thanh trượt chọn thời gian (ví dụ 10 giây) và nhấn nút. File wateringManagement.js gửi POST /api/watering/command với tham số potId=1&action=START&duration=10.

2

WateringCommandServlet xếp lệnh vào Hàng đợi (Command Queue)

Hàm queueCommand(1, "START", 10) lưu lệnh vào ConcurrentHashMap, đặt cờ PUMP_ACTIVE = true, tính thời điểm kết thúc dự kiến (PUMP_END_TIME_MS) và ghi nhật ký tưới vào bảng WateringEvents qua WateringDAO.

3

ESP8266 hỏi lệnh mỗi 1 giây & Cơ chế "Đọc 1 Lần Xóa Luôn" (Consume-on-Read)

Hàm checkCommandFromWebApp() trên ESP8266 gọi GET /api/watering/command?potId=1. Server trả về {"command":"START","duration":10} và lập tức đặt lại lệnh trong hàng đợi về "NONE" để ở giây tiếp theo ESP8266 không bị kích bật lại lần nữa.

4

ESP8266 đóng Relay bật bơm & Đếm giờ Non-blocking bằng millis()

Vi điều khiển xuất mức HIGH ra chân D7 (GPIO13), gán isPumpRunning = true, pumpStartTime = millis() và pumpDurationMs = dur * 1000.

5

Hết giờ hẹn: Tự động ngắt Relay & Gọi API báo OFF về Java Web

Ngay khi currentMillis - pumpStartTime >= pumpDurationMs, ESP8266 hạ chân D7 xuống LOW để tắt máy bơm, đồng thời gọi notifyPumpStoppedToWebApp() gửi POST action=OFF về /api/watering/command. Giao diện Web lập tức đổi trạng thái từ "Đang tưới..." sang "Đang Tắt".

Sự khác biệt giữa tham số ?potId=1 (ESP8266 gọi) và ?potId=1&peek=1 (Web UI gọi) Khi ESP8266 gọi GET /api/watering/command?potId=1, Server sẽ lấy lệnh ra và xóa hàng đợi về NONE. Ngược lại, khi trình duyệt Web gọi kèm &peek=1, Server chỉ trả về trạng thái hiện tại để hiển thị lên màn hình mà không làm mất lệnh đang chờ ESP8266 tới lấy.
Luồng 04 • Cơ chế Ưu tiên Ngắt Khẩn cấp (Instant Stop Override)

Luồng 4: Ngắt Máy Bơm Khẩn Cấp Tức Thì trong vòng < 1 Giây

Nếu người dùng lỡ hẹn giờ tưới quá lâu (ví dụ 60 giây) hoặc thấy nước trong chậu sắp tràn, họ có thể bấm nút "Tắt Bơm Khẩn Cấp" trên Web để ngắt máy bơm ngoài đời thực ngay lập tức.

Bước 01 • Trên Web

Bấm "Tắt Bơm Khẩn Cấp"

JS gửi ngay POST /api/watering/command với potId=1&action=STOP.

Bước 02 • Tại Backend

Ghi đè Hàng đợi Lệnh

WateringCommandServlet đặt lệnh "STOP" vào hàng đợi và hạ cờ PUMP_ACTIVE = false.

Bước 03 • Sau ≤ 1000ms

ESP8266 Đọc Lệnh STOP

Nhờ không dùng delay(), dù đang bơm, mỗi 1 giây ESP8266 vẫn gọi checkCommandFromWebApp().

Bước 04 • Tại Relay D7

Ngắt Bơm Lập Tức

Thực thi digitalWrite(RELAY_PUMP_PIN, LOW) và đặt isPumpRunning = false.

// Đoạn code xử lý lệnh STOP tức thì trong Smart_Irrigation_Projec_IoT.cpp:
else if (cmd == "STOP" || cmd == "OFF") {
  // Bất kể đang hẹn giờ bao nhiêu, có lệnh STOP là tắt lập tức
  if (isPumpRunning) {
    Serial.println("\n>>> WEB RA LENH: Tat bom ngay lap tuc!");
    digitalWrite(RELAY_PUMP_PIN, LOW); // Ngắt Relay -> Tắt bơm
    isPumpRunning = false;
  }
}
Luồng 05 • Phát hiện Sự cố & Cảnh báo Đa kênh

Luồng 5: Cảnh báo Tự động Kép trên Giao diện Web & Email Google Apps Script

Khi phát hiện cây bị khô hạn hoặc đứt dây cảm biến, hệ thống kích hoạt đồng thời 2 kênh cảnh báo độc lập: Hiển thị thẻ cảnh báo trên trang /alerts và bắn Email trực tiếp tới điện thoại người trồng.

Trường hợp 1: Cây Thiếu Nước Động theo Loài Cây (DRY_STRESS)

Ngưỡng độ ẩm tối thiểu không bị fix cứng 30% mà được truy vấn trực tiếp từ loài cây đang trồng trong chậu (SELECT pl.plant_name, pl.ideal_moisture_min FROM Pot p JOIN Plant pl ...) và đồng bộ xuống biến minMoistureThreshold của ESP8266. Khi moisture < minMoistureThreshold, cả Web và Email đều phát cảnh báo theo đúng tên loài cây đó.

Trường hợp 2: Lỗi Phần Cứng (SENSOR_FAULT)

Khi tuột dây DHT11 (isnan(t) || isnan(h)) hoặc lỗi mạch cân HX711 (weight < -500): Hệ thống lập tức phát cảnh báo kỹ thuật SENSOR_FAULT nhắc người dùng kiểm tra lại dây cắm.

Cơ chế Đồng bộ Ngưỡng Độ ẩm Động theo Loài Cây & Chống Spam Email (5 Phút)

Mỗi khi ESP8266 gửi dữ liệu cảm biến (POST /api/sensor/readings) hoặc hỏi lệnh bơm (GET /api/watering/command?potId=1), Server Java trả kèm "plantName", "minMoisture" (từ cột ideal_moisture_min của bảng Plant) và "maxMoisture". Nhờ đó, nếu người dùng đổi cây trồng trong chậu trên Web (ví dụ từ Xương rồng 20% sang Rau cải 50%), mạch ESP8266 tự động cập nhật ngưỡng cảnh báo mới mà không cần nạp lại code: 

// JSON Server trả về cho ESP8266:
{"ok":true, "potId":1, "command":"NONE", "duration":0, "plantName":"Tomato", "minMoisture":45.0, "maxMoisture":75.0}

// Kiểm tra cảnh báo theo ngưỡng động của loài cây trên ESP8266 (Smart_Irrigation_Projec_IoT.ino):
if (currentMillis - lastEmailTime >= emailCooldown || lastEmailTime == 0) {
  if (isnan(t) || isnan(h) || weight < -500) {
    sendEmailViaGoogleScript("SENSOR_FAULT", "Mất tín hiệu từ cảm biến DHT11 hoặc Loadcell...");
    lastEmailTime = currentMillis;
  }
  else if (moisture < minMoistureThreshold) {
    sendEmailViaGoogleScript("DRY_STRESS", "Độ ẩm đất của chậu cây [" + currentPlantName + "] rớt xuống "
      + String(moisture) + "% (thấp hơn ngưỡng tối thiểu " + String(minMoistureThreshold, 1) + "% của loài cây này)!");
    lastEmailTime = currentMillis;
  }
}
Luồng 06 • Ứng dụng Cân điện tử Loadcell HX711

Luồng 6: Hiệu chuẩn Lưu lượng Máy bơm Thực tế (ml/s) & Phân tích Dữ liệu

Điểm sáng tạo nổi bật của đồ án: Sử dụng cân điện tử Loadcell HX711 đặt dưới đáy chậu cây để đo chính xác lượng nước thực tế đã bơm vào chậu, từ đó tự động hiệu chuẩn tốc độ dòng chảy của máy bơm.

1

Ghi nhận khối lượng chậu cây trước khi tưới (Weight_Before)

Trước khi máy bơm chạy, AppDataService lưu lại khối lượng hiện tại của chậu cây từ cảm biến Loadcell (ví dụ 300.0 g).

2

Ghi nhận khối lượng sau khi tưới (Weight_After) & Tính lượng nước thực tế

Sau khi bơm chạy 10 giây và dừng lại, gói tin Telemetry tiếp theo báo cân nặng mới là 425.0 g. Vì khối lượng riêng của nước là $1\text{ g} \approx 1\text{ ml}$, lượng nước thực tế đã vào chậu là $\Delta W = 425 - 300 = 125\text{ ml}$.

3

Cập nhật Hệ số Lưu lượng Bơm (Flow Rate ml/s) trên trang /analytics

Hệ thống chia $\Delta W$ cho thời gian bơm ($\text{FlowRate} = 125\text{ ml} / 10\text{ s} = 12.5\text{ ml/s}$) và hiển thị trực quan trên trang Phân tích & Hiệu chuẩn (analytics.jsp).
